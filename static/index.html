Engine Architecture & Invariants

1. Order Book Data Structures

The order book maintains price-time priority without paying an O(N) scan cost:

  • Bids & Asks: Stored as binary heaps of distinct active prices (O(log P) addition/removal).
  • Price Levels: A hash map of {price -> FIFO deque of orders}. Orders at the same price are matched strictly by arrival sequence.

2. O(1) Amortized Cancellation

Real-world financial markets see ~95% cancels. Traditional order books scan a list on every cancel (O(N)). OrderCore looks up the order by ID in O(1) and sets a tombstone flag. Dead orders are lazily popped when the queue front is walked during matching.

3. Cash Conservation Invariant

The engine enforces strict financial conservation on every single execution:

Δ(Buyer Cash) + Δ(Seller Cash) = 0
Δ(Buyer Position) + Δ(Seller Position) = 0

4. Self-Trade Prevention (STP)

If an incoming aggressive order encounters a resting order from the same account, the resting order is automatically cancelled without printing a wash trade.
